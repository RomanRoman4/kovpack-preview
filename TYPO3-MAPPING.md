# Design-to-TYPO3 contract

The static website in this repository is the visual reference during design work.
Integrate the approved design into the existing `site_kovpack` site package later;
preserve the existing TYPO3 installation and editor data. Integration requires work
and verification: copying this directory into the CMS does not create editable blocks.

Design review covers desktop and phones (owner, 2026-11-12). The phone layer keeps
the desktop look unchanged: all phone rules sit in max-width queries, and elements the
phone scripts create are hidden on desktop. The horizontal menu requires at least
1280 CSS px and a primary input with hover. In other viewports the menu opens as a floating
liquid-glass pane (motion.js): the page behind dims and blurs, a glass drop rests on the
current item and flows to the item touched, submenus unfold in place as liquid glass (motion.js measures the list into `--sub-h` and marks the row `.is-unfolded`: the row and its list sit in a lighter glass well that swells out of the row, the list opens on a soft settling spring, a light streak crosses the glass once, the labels come out of a blur one after another; closing draws it back quickly; one group open at a time; reduced motion: no growth, blur or streak), the current
page in a submenu is marked, the language choices sit side by side on one segmented
pill, and a tap outside or Escape closes it (with a close animation); the menu button is
a keyboard-operable glass pill whose two lines turn into a cross. In compact navigation
the bar keeps one height. Over the home hero the pill is dark glass with a white label and
icon to match the white logo. On scroll the bar and pill fade into light glass with brand
teal details. Inner pages start on a light paper surface. The bar never hides
on scroll, on any page or screen size (owner, 2026-11-24). Under 900px the home
page shows the roll cards instead of the shelf, and every roll card unrolls with the
scroll (product-roll.js sets `--unroll` 0-1 on the product record; no JS or reduced
motion = open): the roll lies across the top, the kraft sheet with eyebrow, name, type,
short text, the first specs and the product link hangs from it, the product photo is a
small taped print beside the name (tablets 601-900px: photo beside the card). Product
pages under 900px: smaller photo stack with the arrows on a glass pill over the photo,
specs as label | value folding after five rows (product-page.js toggle), applications
as a list (icon beside title and text, hairline rows; two columns on tablets), videos as one player with the other clips as thumbnails to pick
(product-page.js, view transition), and a glass enquiry bar at the bottom between the
top button and the form. Also under 900px the distributors intro stacks. Product label
tiles sit side by side (tablets) or stack as slim labels (phones), form fields use 16px text (no iOS zoom), news shows no arrows and
no sideways scrolling (two columns on tablets; on phones the latest post as a card,
the others as compact rows with a small picture), the home contact section is set smaller and back-to-top is a round
glass button; under 600px about strengths put the icon
beside the text. Scroll reveal (motion.js, all widths): sections rise in as blocks and
repeatable items (application tiles, traits, videos, about strengths, enquiry steps,
news cards, `[data-reveal]`) follow one after another; only opacity and transform
animate, one observer, nothing hidden that starts on screen or with reduced motion.

## Current files

- `de/` and `en/`: page markup and relative navigation for both languages.
- `_assets/0f11a716cf5d60e04eb1539b53bf2363/`: current project CSS, JavaScript and assets.
- `_assets/f7dfe1dd89fe6a2f36813ded2dc54cd9/`: exported Camino foundation and fonts.
- `fileadmin/_processed_/` and `typo3temp/assets/`: exported visible images/generated CSS.
- The exported directory hashes are a baseline detail, not a future TYPO3 asset API.
  In CMS templates use extension/FAL asset helpers, not literal exported hash URLs.
- `preview.json` describes the starting export only; it is not a CMS database or a
  live statement that the later standalone design matches the old source commit.

## Integration procedure

1. Freeze an approved preview Git commit as the reference and collect desktop/phone
   screenshots plus interaction expectations for all page types in both languages.
2. Read the existing private project's AGENTS.md, SITE_STRUCTURE.md and architecture.
   Reuse its Camino foundation, page tree and data where compatible; never edit vendor code.
3. Split static HTML into shared Fluid page layouts/partials and editable content blocks.
   Map content to fields/records, respecting localization and repeatable lists. Prefer
   existing supported fields/blocks; extend only for an actual design requirement.
4. Move project CSS/JS/fonts/design assets into `site_kovpack/Resources/Public` and wire
   them through TYPO3 helpers. Import editorial pictures through FAL. Preserve useful
   originals/quality/crops; do not assume exported thumbnails are the master media files.
5. Replace hardcoded text, image paths, navigation and demo form handlers with CMS data
   and supported functionality while keeping the agreed DOM/classes/data attributes where possible.
6. Compare the rendered CMS pages against the approved static reference. Fix differences
   before restoring any automated export. Do not overwrite this design reference with CMS output.
